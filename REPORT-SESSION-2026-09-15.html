Các lỗi đã xử lý trong session

1. Ảnh không hiển thị trong chat (2 nguyên nhân xếp lớp)

  • URL có dấu cách (thư mục /user/images/Don Rosario Vintaloro/) → showdown không parse markdown. Fix: safeImageUrl() encode %20 %28 %29.
  • ST bọc "quoted" thành <q> TRƯỚC markdown → ![..](url "title") vỡ. Fix: snippet bare ![IF Imgen](url) KHÔNG có title; prompt chuyển sang lưu ở message.extra.ifimgen[]. Đã verify bằng showdown thật trên VPS với đúng pipeline <q> của ST 1.18.
  • Ảnh legacy dạng title được migrateChat() tự chuyển khi mở chat (giữ lại prompt cũ làm title-recovered).

2. LLM "biết" nội dung thẻ nhân vật (rò rỉ isolation)

  • Code extension chưa bao giờ đọc description/personality… Rò rỉ nằm ở đường truyền: sendRequest(..., {includePreset:true, includeInstruct:true}) khiến ST merge prompt preset của connection profile (profile đang dùng: "Merge", api custom → api.magimo.vn, preset Blackmore V1.5) — preset mang theo card, persona, world info, assistant_prefill…
  • Fix: includePreset:false, includeInstruct:false, temperature truyền trực tiếp. Payload giờ chỉ có system rule của IF Imgen + user (roster entity tự nhập + K message chat + paragraphs).
  • Guard test sẽ fail nếu bật lại cờ hoặc bất kỳ src/*.js chạm vào field card (description, personality, scenario, first_mes, mes_example, creator_notes, system_prompt, depth_prompt, character_book, world_info).

3. Prompt ra character sheet, không phải cảnh; thừa 2 Rosario

  • Planner prompt viết lại: prompt = mô tả SCENE (pose/action/setting/lighting/camera), KHÔNG phải character sheet; mỗi người chỉ nhắc $keyword một lần; có ví dụ JSON 2 người.
  • resolveEntities: nếu planner nêu $keyword → CHỈ ghép những người được nêu (không còn stamp toàn bộ bind always); không nêu ai mới fallback theo bind.
  • Thừa 2 Rosario / villa nhìn ra biển / suit — ĐÃ TÌM ĐƯỢC NGUỒN: KHÔNG phải extension hay ST, mà là character supplements của proxy Comfy (chi tiết ở mục PENDING).

4. Trigger / Details ($kw.key) — mô hình 2 tầng của user

  • Entity (char/persona) có ô Details, mỗi dòng key: mô tả (outfit/front/back/body/face/nsfw/sfw/note…, key tự do, trùng key tự gộp).
  • Roster gửi planner kèm danh sách token khả dụng (details: $yenka.outfit, $yenka.back). Planner chỉ ĐẶT token, không tự viết nội dung.
  • Mode plan (1 call): expandScene thay token bằng text lưu sẵn → compiler ghép quality/style/cast/scene.
  • Mode refine (2 calls): LLM thứ hai nhận CAST (base + chỉ details được tham chiếu) + STYLE + scene → viết 1 prompt liền mạch; compiler không prepend lại cast (tránh lặp).
  • Token forms: $kw.key, $char.key/$charKey (nhân vật vừa nhắc), $user.key/$userKey/$persona.key. Token lạ bị drop + log.
